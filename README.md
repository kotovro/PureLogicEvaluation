# PureLogicEvaluation — светодиод, кнопка, UART, АЦП на STM32F411

Тестовое задание для **STM32F411CEU6 (WeAct Black Pill)**: светодиод мигает 4/6 с, кнопка
переключает его по схеме «2 нажатия — 2 отпускания», события выводятся в UART 115200 8E1,
АЦП 75 раз в секунду меряет температуру кристалла и напряжение питания, по UART принимаются
команды `?`, `XXXXL`, `XXXXD`.

C++14, STM32CubeMX + HAL, STM32CubeIDE.

## Подключение

| Что | Пин |
|---|---|
| Светодиод (на плате) | PC13, горит при низком уровне |
| Кнопка KEY (на плате) | PA0, замыкает на GND, внутренняя подтяжка вверх |
| USART1 TX → RX адаптера | PA9 |
| USART1 RX ← TX адаптера | PA10 |
| GND адаптера | G |
| ST-Link | SWDIO, SWCLK, GND, 3V3 (разъём на торце платы) |

USB-UART адаптер на 3.3 В; VCC адаптера не подключать.

## Настройки CubeMX (`PureLogicEvaluation.ioc`)

- Тактирование: HSE 25 МГц → PLL → SYSCLK 96 МГц; APB1 /2 (таймеры APB1 — 96 МГц), APB2 /1.
- PC13 — GPIO_Output, метка `LED`; PA0 — GPIO_Input, Pull-up, метка `BTN`.
- USART1 — Asynchronous, 115200, **Word Length 9 Bits (including Parity)**, Parity Even, Stop 1;
  прерывание USART1 включено.
- TIM2 — Internal Clock, Prescaler 0, **Period 1279999** (96 МГц / 75 Гц − 1), TRGO = Update Event.
- ADC1 — Temperature Sensor + Vrefint, PCLK2/4, Scan Enabled. Injected: 2 канала, запуск от
  Timer 2 Trigger Out; Rank 1 = Vrefint, Rank 2 = Temperature Sensor, 480 Cycles (и у regular-канала
  тоже 480). Прерывание ADC1 включено.

## Сборка и прошивка

1. STM32CubeIDE: *File → Open Projects from File System* → папка репозитория.
2. *Project → Build Project*. Проект в режиме C++ (*Convert to C++*): C++14,
   `-fno-exceptions -fno-rtti`.
3. *Run → Debug As → STM32 C/C++ Application*. В *Debug Configurations → Debugger*:
   Reset behaviour **Software system reset** (на SWD-разъёме Black Pill нет NRST),
   Frequency **950 kHz** (дешёвый ST-Link и провода на 4 МГц работают нестабильно).

## Запуск

Терминал на COM-порту адаптера: **115200, 8 бит, Even, 1 стоп-бит**. После сброса:

```
LED ON
LED ON TIME 4000
LED OFF
LED OFF TIME 6000
LED ON
```

| Ввод | Ответ |
|---|---|
| `?` | `VCC 3302` / `TEMP 31` / `LED 4000L` / `LED 6000D` |
| `3500L` | `LED 3500L OK` (новое время свечения, со следующей смены состояния) |
| `5500D` | `LED 5500D OK` (новое время тёмного состояния) |
| `499L`, `10000`, `x`, … | `ERROR` |

Кнопка: `BUTTON ON` / `BUTTON OFF` / `BUTTON TIME <мс>`; при удержании дольше 500 мс один раз
выводятся `TEMP` и `VCC`.

## Тестирование

**На ПК, без платы** — логика проверяется обычным g++ (Windows: MSYS2 или WSL):

```bash
cd tests
g++ -std=c++14 -Wall -Wextra -I../Core/Inc ../Core/Src/logic/*.cpp tests.cpp -o tests && ./tests
```

Тесты моделируют время по миллисекундам и сравнивают вывод с ТЗ, в том числе дословно пример из п.3.

**На плате**, в терминале:

| Действие | Ожидается |
|---|---|
| Ждать 10 с | `LED ON TIME 4000`, `LED OFF TIME 6000` |
| Клики 1, 2 | светодиод переключается в момент нажатия |
| Клики 3, 4 | переключается в момент отпускания; дальше цикл повторяется |
| Удержание > 0.5 с | один раз `TEMP` и `VCC` |
| `?`, `3500L`, `abc` | ответы из таблицы выше |
| Терминал с Parity Odd, любой символ | `ERROR` |

## Как устроено

```
Core/Src/main.c, usart.c, adc.c, tim.c, ...   сгенерированы CubeMX; в main.c вызваны app_init() и app_step()
Core/Src/app_main.cpp     связь с HAL: приём UART, АЦП, светодиод, кнопка, основной цикл
Core/*/logic/             логика ТЗ без HAL (тестируется на ПК)
  app                       class App: события -> переключения -> строки вывода
  debouncer, led_timer      фильтр дребезга, таймер светодиода
  command_parser            разбор команд
  sensors                   блочное среднее по 10 измерениям, пересчёт в °C и мВ
tests/tests.cpp           тесты логики
```

- **Суперцикл.** Прерывания только складывают данные: принятые байты — в кольцо, измерения АЦП — в
  суммы текущего блока. Логика работает в основном цикле раз в 1 мс, между итерациями ядро спит (`WFI`).
- **Кнопка** опрашивается раз в 1 мс, фильтр дребезга 10 мс — реакция 10–20 мс (требование ≤ 50 мс).
- **UART.** Приём — по прерыванию, по одному байту; байт с ошибкой чётности даёт `ERROR`. Вывод
  блокирующий (`HAL_UART_Transmit`, ~2 мс на строку): приём при этом не теряется, а пропущенные
  миллисекунды основной цикл догоняет.
- **АЦП.** TIM2 по событию переполнения 75 раз в секунду запускает инжектированную группу ADC1
  (VREFINT + датчик температуры) без участия программы. Прерывание АЦП копит суммы по 10 измерениям
  и, набрав блок, запоминает их (новое среднее каждые ~133 мс). Температура и напряжение считаются по
  заводским калибровкам, с поправкой на реальное VDDA, только в целых числах.

## Допущения по ТЗ

1. **п.2В**: счёт по кликам — клики 1–2 срабатывают на нажатии, 3–4 на отпускании; каждое нажатие —
   ровно одно переключение.
2. **Время нажатия** — между отфильтрованными фронтами (оба задержаны фильтром на одинаковые 10 мс).
3. **Среднее по 10** — блочное: каждые 10 измерений (~133 мс) считается новое среднее, на запрос
   выдаётся последнее. Усредняются сырые коды, затем пересчёт.
4. **п.4Г**: «превысит 500 ms» — строго больше; строки выводятся в момент превышения, один раз за
   нажатие. Порядок TEMP/VCC — как в п.4Г, в ответе на `?` — VCC/TEMP, как в п.5А.
5. **Новые времена** применяются со следующей смены состояния; на `?` выводятся заданные значения.
6. **Команды** — 1–4 цифры и заглавная `L`/`D`, 500..9999; в ответе — строка как принята (`0600L`).
   CR/LF вне команды игнорируются.
7. **ERROR** выводится на каждый ошибочный символ: недопустимый, с ошибкой чётности, 5-я цифра,
   `L`/`D` без цифр, обрыв числа концом строки; и на значение вне диапазона.
8. Первые ~133 мс после старта первый блок из 10 измерений ещё не набран — вместо VCC/TEMP выводится `ERROR`.
